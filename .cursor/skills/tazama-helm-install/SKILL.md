# Install Tazama on Kubernetes

You are installing the Helmfile stack in `tazama-Helms/`. Do the work yourself. Do not dump the README and stop. Do not commit `values/secrets.yaml`.

For flag recipes (CMS, BIAR, relays, selectors) see [commands.md](commands.md).

## Hard rules

- **Windows:** only `.\tazama.cmd ...`. Never `.\tazama.ps1` (execution policy blocks it).
- **Linux/macOS:** `./tazama.sh ...`.
- Run wrappers from `tazama-Helms/` (the folder that contains `tazama.cmd` and `helmfile.yaml.gotmpl`).
- First install: `sync`, not `apply`.
- Default shape: `-Profile core -Cloud onprem` unless the user asked for `full`, a cloud, or extra packages.
- Kind / k3s / kubeadm / Docker Desktop Kubernetes → `-Cloud onprem`. EKS/GKE/AKS → matching cloud. Never mix Kind with `-Cloud eks`.
- On-prem ingress stays **NodePort**. Kind has no cloud load balancer; `LoadBalancer` hangs Helm `--wait`.
- TMS Service port is **3000**, not Docker Compose 5000. Admin is **5100**.
- No Hasura. Config is admin-service only.
- Helmfile must be **1.x** (`helmfile version`). Entry file is `helmfile.yaml.gotmpl`.
- Generated passwords are 20-character URL-safe strings. Auth RSA keys are generated by the wrapper into `values/secrets.yaml`. Do not `kubectl create secret generic tazama-auth-keys`.

## Workflow

Copy and track:

```
Install:
- [ ] 1. Tools on PATH (kubectl, helm, helmfile 1.x, openssl/git; docker if Kind)
- [ ] 2. Cluster reachable (`kubectl get nodes`)
- [ ] 3. secrets.yaml present (wrapper can create it)
- [ ] 4. sync the requested profile/cloud
- [ ] 5. pods Ready in namespace tazama
- [ ] 6. TMS health (port-forward 3000 or ingress)
- [ ] 7. Optional: load tms-configuration via `configure -Truncate` / `configure --truncate`
- [ ] 8. Optional: Keycloak tenant groups via `tenant` (TAZAMA.ORG + 12 users)
- [ ] 9. Optional: Postman e2e via `e2e` (needs a local tazama-lf/postman clone and Newman)
```

Ask the user only if the target cluster or profile is ambiguous. If they said “install it”, default to **core / onprem** on whatever cluster `kubectl` already points at. If there is no cluster and Docker is available, create Kind `tazama-cluster`.

### 1. Tools

Check: `kubectl version --client`, `helm version`, `helmfile version`, `openssl version`. On Windows also try `%USERPROFILE%\bin` (wrapper looks there).

Missing tools:

- **Windows:** Docker Desktop if using Kind. Then `winget install --id Kubernetes.kubectl -e`, `Helm.Helm`, `Kubernetes.kind`. Helmfile: zip from https://github.com/helmfile/helmfile/releases (`helmfile_*_windows_amd64.zip`) → `helmfile.exe` on PATH (often `%USERPROFILE%\bin`). openssl via Git for Windows.
- **macOS:** `brew install kubectl helm helmfile kind git` plus Docker Desktop or Colima.
- **Linux:** official kubectl binary, `get-helm-3`, Helmfile 1.x tarball (`linux_amd64` or `linux_arm64`), Kind from https://kind.sigs.k8s.io/dl/latest/. Docker Engine if using Kind.

If `helmfile version` is 0.x, stop and install 1.x.

Optional: `helm plugin install https://github.com/databus23/helm-diff`. Missing helm-diff is fine; `sync` does not need it.

### 2. Cluster

`kubectl get nodes` must work. Honor `KUBECONFIG` if set. The wrapper passes `--kubeconfig` when that env var is set.

Pick one:

| Situation | Action | Cloud flag |
| --- | --- | --- |
| Nodes already listed | Use that cluster | `onprem` unless it is clearly EKS/GKE/AKS |
| `tazama-Helms/infra/aws/kubeconfig.yaml` exists | `$env:KUBECONFIG` to that file (k3s box) | `onprem` |
| No cluster, Docker running | `kind create cluster --name tazama-cluster` | `onprem` |
| User named EKS/GKE/AKS | They must already have that kubecontext | `eks` / `gke` / `aks` plus `-IngressDomain` |

Kind is a laptop sandbox, not production. Confirm StorageClass exists (`kubectl get storageclass`) before a cloud or bare-metal install.

Helmfile creates namespace `tazama`. Do not require `kubectl create ns`.

### 3. Secrets

If `tazama-Helms/values/secrets.yaml` is missing, the wrapper copies `values/secrets.example.yaml` and fills random passwords plus an Auth RSA pair. You may run `.\tazama.cmd secrets` or `./tazama.sh secrets` first (no cluster). Never commit that file. Never paste `kubectl get secret` base64 back into it.

To rotate: `.\tazama.cmd secrets -GenerateSecrets` or `./tazama.sh secrets --generate-secrets`, then sync again. Changing `postgres.password` after Postgres has initialized does not rewrite the role; wipe the PVC or `ALTER USER`.

### 4. Deploy

Windows:

```powershell
cd tazama-Helms
.\tazama.cmd sync -Profile core -Cloud onprem
```

bash:

```bash
cd tazama-Helms
chmod +x tazama.sh
./tazama.sh sync core onprem
```

If the user asked for the full stack: `-Profile full` / `./tazama.sh sync full onprem`.

Cloud examples (kubeconfig already targeting that cluster):

```powershell
.\tazama.cmd sync -Profile core -Cloud eks -IngressDomain tm.example.com
```

```bash
./tazama.sh sync core eks --ingress-domain tm.example.com
```

`sync` can take many minutes (Postgres init SQL, Keycloak realm import, 30+ rule images). Set a long command timeout. Do not kill it at the first idle period.

If Helm hangs ~900s on ingress-nginx: on-prem Service type must be NodePort, not LoadBalancer.

### 5. Verify

```powershell
kubectl get pods -n tazama
```

Wait until Postgres and processors are Ready. First boot: SQL `00-CREATE.sql` and `10-core-config.sql`, Keycloak realm import.

Port-forward (onprem without ingress):

```powershell
kubectl port-forward -n tazama svc/tms-service 3000:3000
kubectl port-forward -n tazama svc/admin-service 5100:5100
```

Windows: `curl.exe http://localhost:3000` (not the `curl` alias). Linux/macOS: `curl http://localhost:3000`. Expect `{"status":"UP"}`.

With ingress: `http://tms.<domain>` and `http://admin.<domain>`.

### 6. Load configuration (optional)

Core already has sample rules 901/902 on `pacs.002.001.12` tenant `DEFAULT`. A full typology set needs private [frmscoe/tms-configuration](https://github.com/frmscoe/tms-configuration).

If that repo is cloned next to `tazama-Helms/` (or `-TmsConfigPath` / `--tms-config-path`):

```powershell
.\tazama.cmd configure -Truncate
```

```bash
./tazama.sh configure --truncate
```

Use `-Truncate` / `--truncate` on the first load. Sample 901/902 is already in Postgres; without it admin-service returns 500 `rule_pkey`. That port-forwards admin-service, fetches a JWT (`tazama-user@tazama.org` unless `-SkipAuth` / `--skip-auth` or `-AuthUser` / `--auth-user`), POSTs `curl/` payloads, activates `network_map/4.0.0` with cascade reload, and restarts ED / TP / EA.

Do not install Hasura. Do not run the Hasura Postman folder.

Keycloak `--import-realm` only loads the skeleton (same JSON as tazama-stack). Nested `TAZAMA.ORG` groups and `tazama-api-client@tazama.org` need:

```powershell
.\tazama.cmd tenant
```

```bash
./tazama.sh tenant
```

TMS test traffic: pacs.008 / pacs.002 to `http://localhost:3000`. Until a full map is activated, Event Director rejects pacs.008 (`txTp` missing). Results: database `evaluation`, table `evaluation`.

After `configure -Truncate` / `configure --truncate`, run the public Postman AUTH collection (Newman 4.1 tenant-001, admin-service report, TMS 3000). Clone [tazama-lf/postman](https://github.com/tazama-lf/postman) next to this repo. Do not vendor it. Unauthenticated posts return 401 when AUTH is on:

```powershell
.\tazama.cmd e2e
```

```bash
./tazama.sh e2e
```

## After install (what is running)

`core` includes: Postgres, NATS, Valkey, admin-service :5100, TMS :3000, Event Director / Flow / Typology Processor / Adjudicator, Auth :3020, Keycloak :8080 (`quay.io/keycloak/keycloak:23.0.6`, realm `tazama`), relays to NATS, public rule images. `auth.authenticated` defaults to **true** (JWT on TMS, admin, CMS, studios, DEMS, DEAPI). Pass `-NoAuth` / `--no-auth` for a lab. `-EmptyRealm` / `--empty-realm` imports Keycloak groups with no login users; run `tenant` before `configure`. Studios, CMS, BIAR stay off unless flagged.

## Failures

| Symptom | Fix |
| --- | --- |
| `running scripts is disabled` | You used `tazama.ps1`. Switch to `tazama.cmd`. |
| `helmfile is not on PATH` | Install Helmfile 1.x; Windows often `%USERPROFILE%\bin`. |
| Pods Pending / PVC Pending | No StorageClass. Set `storageClass` in `environments/cloud/<name>.yaml`. |
| ImagePullBackOff | Docker Hub rate limit; set pull secret in `values/secrets.yaml`. |
| Keycloak CrashLoop on reused PVC | `CREATE DATABASE keycloak;` if missing. Realm ConfigMap `keycloak-realm`. |
| ED: no network map for DEFAULT | Load/activate tms-configuration, then restart ED/TP/EA. |
| 500 `rule_pkey` on configure | Sample 901/902 already in Postgres. Use `.\tazama.cmd configure -Truncate` or `./tazama.sh configure --truncate`. |

Do not `destroy` unless the user asked to uninstall.
